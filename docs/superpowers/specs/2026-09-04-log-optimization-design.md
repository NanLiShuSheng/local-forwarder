# 日志功能优化设计

## 目标

优化日志页面的排查效率，支持清空当前代理实例的日志、在请求参数源码与浏览器式键值解析结果之间切换，并将应答原文一键带入 JSON 可视化页面。

本次只调整日志查看与页面联动，不改变现有日志采集、截断和最多保留 2000 条的规则。

## 已确认的交互方案

采用「分段切换」布局：请求参数和应答数据分别作为独立区块；请求参数区提供「源码 / 解析结果」切换，应答区保留原文并提供「回填到 JSON 可视化」按钮；日志工具栏提供「清空日志」按钮。

已确认的行为如下：

- 清空范围仅为当前选中的代理实例。
- 请求解析结果使用浏览器常见的键值列表，每行显示 `key: value`，不使用对象树。
- 回填动作自动跳转到 JSON 可视化页面，并替换当前输入内容。
- 非法 JSON 也允许回填，JSON 页面显示解析失败并保留原文，便于继续编辑。

## 日志清空

日志目前保存在当前 `ForwardingService` 的内存缓冲区中。新增 `clearLogs` 能力，沿用当前选中代理实例的管理链路：

1. `LogPanel` 点击「清空日志」并调用 App 提供的清空回调。
2. renderer 通过新增的 `runtime:logs:clear` IPC 通道请求主进程清空日志。
3. `ForwardingServiceManager` 将请求转发给当前实例的 `ForwardingService`。
4. `ForwardingService.clearLogs()` 清空 `logBuffer`。
5. 成功后 renderer 清除选中详情并刷新列表；清空后的新请求仍会正常记录。

清空失败时保留现有日志，并通过现有全局错误提示展示失败原因。日志不持久化，因此该操作不修改配置文件。

## 请求参数源码与解析结果

现有 `requestParams` 保留完整请求行和请求体，例如请求方法、路径、查询字符串和空行后的表单内容。日志详情增加两个视图：

- 「源码」直接显示现有原文，保持换行和 URL 编码内容不变。
- 「解析结果」解析请求行、查询参数和请求体，并以分区键值行显示：

  ```text
  请求方法: GET
  请求路径: /reqxml

  查询参数
  Action: 100

  请求体
  account: 600554432
  ```

查询参数和表单请求体使用 `URLSearchParams` 解析；重复键逐行保留。无法识别的请求体不丢弃，解析结果中以原始文本显示，并提供回看源码的入口。解析逻辑放在无 UI 依赖的共享模块中，供单元测试覆盖。

应答数据在日志页面继续显示原文，不强制在日志页解析为对象；其可视化由 JSON 页面完成。

## 应答回填到 JSON 可视化

App 增加一次性 JSON 回填状态和两个页面回调：

- `LogPanel` 接收 `onFillJson(responseData)`，点击按钮时传递当前日志的应答原文。
- App 保存回填文本、切换页面到 `json`，并将文本传入 `JsonPreviewPage`。
- `JsonPreviewPage` 收到新回填文本后更新输入框、重新解析、重置选中路径和展开状态，再通知 App 清除一次性回填状态。

合法 JSON 直接进入现有树形、表格和原始 JSON 视图；普通文本、截断提示或其他非法 JSON 仍填入输入框，并由现有解析错误状态提示用户。

数据流如下：

```text
日志详情 --responseData--> App 回填状态 --> JSON 可视化输入框 --> 现有 JSON 解析与视图
日志工具栏 --clearLogs IPC--> 主进程 --> 当前 ForwardingService.logBuffer
```

## 错误处理与边界

- 没有应答数据时不显示或禁用「回填到 JSON 可视化」按钮。
- 二进制响应摘要可以回填，但 JSON 页面按非法 JSON 处理，不伪造结构化结果。
- 清空日志期间产生的新日志不阻塞清空操作；清空完成后的新日志仍可显示。
- 切换代理实例后，日志清空和日志查看始终作用于当前实例。
- 保持现有日志筛选、最近 200 条展示、详情关闭和响应截断行为不变。

## 测试

- 共享解析器：覆盖请求行、查询参数、表单请求体、重复键和不可解析原文保留。
- 核心运行时：验证 `clearLogs()` 只清空当前服务缓冲区，并且清空后仍可追加新日志。
- IPC 与 preload 契约：验证新增清空日志通道和 API 暴露稳定。
- renderer 日志契约：验证清空按钮、源码/解析结果切换、键值行、回填按钮和错误空状态。
- renderer 导航契约：验证日志回填触发 JSON 页面和 JSON 页面接收新输入。
- 完成后运行构建、相关 renderer/core 测试和完整 `npm test`。
