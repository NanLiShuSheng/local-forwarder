# 日志列表与详情同屏设计

## 目标

当日志数量较多时，用户点击日志后可以在同一个日志工作区内同时看到日志列表和详情，不需要把整页滚动到日志面板底部。日志列表和详情各自处理内容滚动，保持现有筛选、排序和详情字段行为。

## 方案

将 `LogPanel` 的内容组织为双栏日志工作区：

1. 左侧为日志列表，保留当前数量、级别筛选、文本筛选和倒序展示。
2. 左侧列表设置独立的纵向滚动区域；日志较多时只滚动列表，不推动详情或整页。
3. 右侧为当前选中日志的详情区域，继续显示“请求参数”和“应答数据”，点击列表项后即时更新。
4. 详情区域保持在日志工作区内；请求参数和应答数据保留各自的内容滚动，避免超长内容撑高页面。
5. 未选择日志时右侧显示空状态；关闭按钮清除当前选择。
6. 窄屏下双栏折叠为上下布局，列表和详情仍属于同一个日志面板，避免详情回到整个页面最底部的不可控位置。

采用双栏方案，不使用抽屉覆盖列表，以便用户频繁切换日志并保留上下文；不改变 `LogEntry` 数据结构、筛选算法、排序顺序或 IPC 数据流。

## 边界与错误处理

- 没有日志时保留现有“暂无日志”提示，详情区显示未选择状态。
- 没有请求参数或应答数据时继续显示“无”。
- 长日志文本在详情内部滚动并换行，不产生页面级横向滚动。
- 详情关闭只清除选中项，不清除筛选条件或日志列表。

## 测试

- 更新 renderer 日志测试，验证 `LogPanel` 保留日志详情字段和选择/关闭行为。
- 验证样式包含日志工作区、列表独立纵向滚动、详情区域和窄屏布局约束。
- 运行日志测试、renderer 测试和完整 `npm test`，确认现有日志筛选与其他页面无回归。
