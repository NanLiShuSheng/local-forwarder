# 登录缓存与代理实例关联设计

## 目标

让本地变量保持工作区级共享，让登录缓存按代理实例独立保存，并让登录请求捕获的值立即反映在当前代理的缓存页面和概览卡片中。

## 数据模型

工作区增加 `sharedValues`，每个代理实例增加 `loginCache`：

```text
ProxyWorkspace
  sharedValues: Record<string, string>
  instances[]
    config: AppConfig              # 网络、规则、请求等配置
    loginCache: Record<string, string>
```

旧版本工作区没有 `sharedValues` 和 `loginCache`，迁移时把旧实例 `config.localValues` 作为该实例的登录缓存，工作区共享变量初始化为空，避免已有 Token 扩散到新代理。

## 运行时与保存

代理实际使用的变量为 `sharedValues` 与当前实例 `loginCache` 的合并结果，登录缓存覆盖同名共享变量。共享变量修改后，已运行的所有代理会更新运行时变量；登录缓存修改只更新对应代理。新增代理的登录缓存为空，复制代理不复制登录缓存。

手动请求识别为登录请求，或普通 HTTP 响应自动捕获登录字段时，只写入当前实例的 `loginCache`。保存完成后概览摘要、当前配置和登录缓存页面都能读到最新值。

## 页面行为

“本地变量”页面编辑工作区共享变量；“登录缓存”页面编辑当前选中代理的缓存。缓存输入框由当前代理缓存格式化生成，显示 `KEY = VALUE`，缓存数量与实际内容一致。概览每个代理实例显示缓存项数量，当前实例详情显示缓存状态。

## 测试范围

覆盖工作区校验与旧数据迁移、共享变量对多个运行实例生效、登录捕获只写当前实例、手动登录请求写入当前实例、概览缓存数量和页面输入框同步。完成后运行全量测试、构建和 DMG 校验。
