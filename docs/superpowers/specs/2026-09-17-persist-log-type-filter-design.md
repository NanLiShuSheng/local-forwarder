# 日志类型筛选记忆设计

## 目标

日志页面首次使用时默认选择 `/reqxml`；用户手动切换类型后，将选择保存到浏览器本地存储，使应用重启或重新进入日志页面后仍恢复上次选择。

## 范围

本次只增加日志类型筛选值的本地持久化，不改变日志采集、类型解析、固定/动态选项、级别筛选、文本筛选、详情展示或日志清空行为。

不写入应用配置文件，不增加 IPC，不持久化日志内容，也不持久化级别和文本筛选条件。

## 持久化约定

- 存储键固定为 `local-forwarder.log-type`。
- 没有存储值、存储值为空或存储访问抛错时，使用 `/reqxml`。
- 用户通过类型下拉框手动选择后，立即写入选择值，包括 `all`（界面文案为“全部”）和动态 pathname。
- localStorage 不可用时，筛选仍在当前页面内正常工作，持久化失败不得阻塞日志页面。

## 状态与数据流

```text
localStorage
  -> 读取已保存类型（失败则 /reqxml）
  -> LogPanel 初始类型状态
  -> 类型选项失效时按现有规则显示“全部”
  -> 用户手动选择
  -> 更新 React 状态并写回 localStorage
```

初始读取只负责提供状态初值，不在渲染过程中写入默认值。动态 pathname 暂时不出现在当前日志选项中时，页面继续使用现有的“全部”回退逻辑，但不覆盖本地存储值，以便该 pathname 再次出现时恢复用户选择。

## 实现边界

- 新增无 UI 依赖的偏好读写辅助模块，采用与现有主题偏好相同的 storage adapter 方式，便于测试。
- `LogPanel` 使用惰性初始状态读取已保存类型，在类型下拉框的 `onChange` 中同时更新状态和持久化值。
- 读写辅助函数捕获 storage 异常，并返回/保持默认行为。
- 不使用 URL、Electron 配置或主进程存储，避免扩大本次改动范围。

## 测试与验收

- 读不到值、空值和非法 storage 访问回退 `/reqxml`。
- 写入 helper 能保存类型值，并吞掉写入异常。
- `LogPanel` 源码和行为测试确认初始值来自本地存储，手动选择会写入，`all` 和动态 pathname 也能保存。
- 现有类型筛选测试继续覆盖默认 `/reqxml`、全部、动态选项、类型/级别/文本 AND 筛选和最近 200 条倒序。
- 通过 renderer 定向测试、`npm run build` 和完整 `npm test`。
