# Windows 安装器版本拦截设计

## 目标

优化 Windows NSIS 安装流程：安装器启动时比较当前已安装版本与安装包版本，避免同版本重复安装，并阻止降级安装。升级时保留现有应用数据和用户配置。

## 行为规则

以 Windows 卸载注册表中的 `DisplayVersion` 为已安装版本来源：

| 当前状态 | 结果 |
| --- | --- |
| 没有已安装版本 | 正常安装 |
| 安装包版本高于当前版本 | 正常升级 |
| 安装包版本等于当前版本 | 提示已安装相同版本并退出 |
| 安装包版本低于当前版本 | 提示已安装更高版本并退出 |
| 注册表中没有版本值 | 按未安装处理，允许安装 |

版本比较使用 NSIS 的版本比较能力，按数字版本段比较。当前项目使用 `major.minor.patch` 形式；构建元数据不参与判断。

## 安装器实现

在 electron-builder 的 NSIS `customInit` 扩展点执行检查，位置早于安装文件解压和覆盖：

1. 读取当前 NSIS 注册表视图下的 HKCU 和 HKLM 卸载项。
2. 读取 `DisplayVersion`，取已安装应用的有效版本。
3. 与安装包注入的 `${VERSION}` 比较。
4. 同版本或降级时显示中文提示，并调用 `Abort` 终止安装。
5. 新版本或未找到版本时继续执行 electron-builder 默认安装流程。

注册表键使用 electron-builder 提供的 `${UNINSTALL_REGISTRY_KEY}`，不硬编码应用 GUID。安装目录、用户数据目录和卸载入口均沿用现有 NSIS 配置。

## 数据与兼容性

- 版本拦截发生在文件写入前，不删除、不迁移、不覆盖用户数据目录。
- 升级沿用 electron-builder 的现有安装目录和卸载注册表逻辑。
- 未找到旧版本注册表值时保持兼容，允许首次安装或旧版遗留安装继续安装。
- 应用正在运行时沿用现有 NSIS 单实例行为；本次不扩展进程关闭和数据备份逻辑。

## 测试与验收

- 增加安装器配置契约测试，确保自定义 NSIS include 被启用，并包含版本比较和提前终止逻辑。
- 生成 Windows x64 NSIS 安装包，验证 PE 文件、资源文件和安装器存在。
- 在 Windows 环境验收四种路径：首次安装、同版本重复安装、升级、降级拦截。
- 同版本和降级场景确认安装目录文件及应用数据修改时间不发生安装覆盖；升级场景确认原有配置仍可读取。
