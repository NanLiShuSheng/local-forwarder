# 静态加密与字符串工具行为调整规格

## 目标

调整两个现有功能：

1. 目录加密递归扫描时不再排除名为 `dist` 的目录，`dist` 及其普通文件按现有规则正常生成 `.d` 输出。
2. 字符串工具的编码、解码及其他静态处理不依赖转发服务是否启动。操作结果必须先在渲染层由纯函数计算并展示；草稿持久化仍可继续使用，但持久化失败不能阻止或撤销静态处理结果。

## 设计

### 加密扫描

`src/core/encryption/encryptor.ts` 保留隐藏项、`node_modules` 和 `.map` 文件过滤，仅删除 `dist` 目录过滤。输出目录安全校验、临时目录、编码器调用和状态文件行为不变。加密页面文案同步说明 `dist` 会被处理。

### 字符串工具

`StringToolPage` 执行操作时先调用 `applyStringOperation`，立即更新本地草稿中的 `outputText`，静态操作的成功与否不由 `onChange` 或服务状态决定。随后尝试持久化草稿；如果保存失败，只显示保存提示，保留已经计算出的结果。

这样不扩大服务运行态配置写入权限，也不让字符串工具引入新的 IPC 或运行时依赖。服务停止时仍保持原有的草稿持久化能力。

## 错误处理

- `dist` 文件的编码失败沿用现有加密错误处理，任务终止并清理临时目录。
- 字符串处理本身抛出的错误（例如非法 URL 编码或非法 JSON）继续显示为处理错误，不写入错误结果。
- 字符串工具草稿保存失败只显示“结果已生成，但配置未保存”的可读提示，不覆盖结果文本。

## 测试标准

- 加密核心测试确认 `dist/bundle.js` 被收集、加密并输出为 `dist/bundle.js.d`，隐藏项、`node_modules` 和 `.map` 仍被过滤。
- renderer 字符串工具测试确认执行路径先得到静态结果，即使持久化回调返回失败，结果仍保留；页面源码不把服务运行状态作为处理前置条件。
- 运行目标测试、全量 `npm test`、打包验证；安装阶段使用生成的 macOS DMG 安装应用。
