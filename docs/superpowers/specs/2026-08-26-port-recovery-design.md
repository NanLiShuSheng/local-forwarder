# 808x 端口自动恢复设计

## 目标

当服务启动监听 `8080`–`8089` 端口并收到端口占用错误时，自动结束监听该端口的进程，确认端口释放后重试一次启动。其他端口保持现有行为，不自动结束占用进程。

## 方案

新增独立的端口恢复模块，使用 macOS `lsof` 查询 TCP LISTEN 状态的进程 PID。恢复流程如下：

1. 仅当端口范围为 `8080`–`8089` 且启动错误码为 `EADDRINUSE` 时触发。
2. 查询端口监听 PID，跳过当前 Node/Electron 进程。
3. 向剩余 PID 发送 `SIGTERM`，轮询端口是否释放。
4. 超时后向仍存在的 PID 发送 `SIGKILL`，再次轮询。
5. 端口释放后重试 HTTP 监听一次；恢复失败则返回原始启动错误。

端口恢复依赖通过接口注入，测试不调用真实 `lsof` 或结束进程。生产环境使用真实系统实现。

## 错误处理

- `8080`–`8089` 以外的端口不执行恢复。
- 非 `EADDRINUSE` 的启动错误不执行恢复。
- `lsof` 无法执行、没有可识别 PID、权限不足或端口仍未释放时，服务进入错误状态并显示端口占用信息。
- 不会结束当前应用自身进程。

## 测试

- 覆盖 808x 范围判断和边界端口。
- 覆盖 SIGTERM 后端口释放。
- 覆盖 SIGTERM 无效时的 SIGKILL 兜底。
- 覆盖非 808x 端口不恢复。
- 覆盖服务收到 `EADDRINUSE` 后恢复并成功启动。
