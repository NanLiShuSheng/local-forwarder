# 目录 URL 输入设计说明

## 目标

让“加密”页面的加密前目录、加密后目录，以及“设置”页面的项目目录同时支持 Finder 复制的 `file:///...` URL、普通本地绝对路径和原有系统目录选择器。三种方式最终都保存为同一种本地绝对路径。

## 交互

- 目录输入框改为可编辑，支持粘贴 `file://` URL 或本地路径。
- 输入框失焦或按 Enter 时解析并保存；保存失败时显示中文错误，并保留上一次有效值。
- 加密页面的“选择目录”按钮继续打开系统目录选择器，选择结果与手动输入走同一套状态和保存逻辑。
- 设置页面的“选择项目目录”按钮保持原有行为。
- 加密任务运行时，两个加密目录输入框和按钮禁用；设置页面不改变原有服务配置保存行为。

## 数据边界

- 共享层提供纯函数，将 `file://` URL 使用标准 URL 解码为绝对路径；普通绝对路径原样规范化；空值和非本地协议拒绝。
- 加密目录通过新增的受信任 IPC 保存偏好接口写入 `encryption-preferences.json`，复用现有偏好读写逻辑。
- 项目目录通过现有 `config:save` IPC 写入内部配置。
- Renderer 不访问 Node 文件系统或 URL 转换的 Node 专有 API。

## 错误处理

- 只接受本地 `file:` URL；`http:`, `https:` 等远程 URL 显示“目录 URL 必须是本地 file URL”。
- 无效 URL、相对路径和空值显示“目录路径无效”。
- IPC 或配置保存失败显示返回的中文错误，不清空原值。

## 测试

- 共享解析函数覆盖 URL 解码、普通路径、非本地 URL、相对路径和空值。
- 偏好保存测试覆盖手动输入后只更新一个目录且保留另一个目录。
- Electron 合同测试覆盖新的保存偏好 IPC、preload API 和主进程 handler。
- Renderer 合同测试覆盖三个输入框可编辑、Enter/失焦保存及选择按钮仍存在。
