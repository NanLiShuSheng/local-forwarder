# 多代理实例并行转发设计

## 目标

在保留现有加密、手动请求、规则、缓存、登录缓存和日志能力的前提下，将应用从单个转发服务升级为多个独立代理实例，使用户可以同时启动两个或更多不同端口、不同上游地址的转发。

## 方案

新增 `ForwardingServiceManager` 作为实例生命周期和选择状态的协调层。每个实例拥有独立的 `AppConfig`、`ForwardingService`、缓存运行时、日志缓冲区和状态；管理器只负责实例集合、当前实例、持久化和端口冲突校验。现有 `ForwardingService` 保留单实例职责，不把多个监听器塞进同一个服务对象。

实例数据持久化为独立的工作区文件。应用启动时优先读取工作区；如果工作区不存在，则读取现有 `config.json`，迁移为一个名为“默认代理”的实例并写入工作区，确保升级不丢失原有配置。工作区保存实例名称、实例 ID、当前实例 ID 和完整 `AppConfig`，使用原子写入并复用现有配置校验。

## IPC 与数据流

保留现有 `getConfig`、`saveConfig`、`start`、`stop`、`status`、`logs`、`sendRequest` 等接口的语义，使它们作用于当前选中实例；新增实例列表、选择实例、新增实例、复制实例和全部实例状态接口。请求发送使用当前实例的超时时间，并把自动提取的登录值合并回当前实例。加密 IPC 不绑定代理实例，继续使用全局加密目录偏好和全局加密任务。

所有配置写入均经过实例管理器：当前实例停止时允许保存配置，运行中仍拒绝修改监听端口和转发配置。启动前管理器检查当前实例与其他运行实例的绑定主机和端口，发现冲突时返回明确错误，不触发会结束其他实例的端口恢复逻辑。

## 页面行为

在概览页加入代理实例列表和当前实例详情。列表显示名称、监听端口、上游地址、运行状态和请求数；选择列表项切换当前实例；“新增代理”创建停止状态的默认实例；“复制当前实例”复制当前配置并分配未占用端口；当前详情页提供单实例启动/停止。

原有侧边导航和加密、请求、字符串、变量、登录缓存、日志、设置页面保留。切换实例时，配置类页面、请求超时上下文、登录缓存和日志切换到当前实例；加密页面继续保持全局状态。

## 错误处理

- 实例 ID 不存在：返回稳定的“代理实例不存在”错误。
- 新实例端口已被其他运行实例占用：拒绝启动并提示冲突实例名称和端口。
- 配置保存或工作区写入失败：保留内存状态，返回错误，不破坏旧文件。
- 单个实例启动失败：只将该实例置为错误状态，不影响其他运行实例。
- 应用退出：管理器按实例停止全部运行服务后再退出。

## 验收标准

1. 旧版单实例配置首次启动后可作为“默认代理”加载，原有配置、加密和请求能力可用。
2. 至少创建两个实例，分别设置不同监听端口和上游地址，并可同时启动。
3. 切换实例后，端口、状态、请求计数、日志和配置显示对应实例。
4. 相同绑定主机和端口的两个实例不能同时启动，且不会停止已运行实例。
5. 原有加密全量/增量按钮、手动请求和全量测试继续通过。
