# 加密目录历史选择设计说明

## 目标

为“加密”页面的“加密前文件夹目录”和“加密后文件夹目录”增加可持久化的历史目录选择能力，交互复用“转发地址”的右侧箭头下拉模式。两个目录字段分别维护历史，互不混用。

## 方案与范围

采用应用偏好文件持久化历史目录，不使用 Renderer 的 `localStorage`，也不依赖系统目录选择器自己的最近目录列表。历史目录由主进程统一读写，应用重启后仍可用。

本次只增加历史记录和选择交互，不改变现有目录 URL 解析、加密校验、全量/增量加密和任务执行逻辑。

## 数据模型与兼容

`EncryptionPreferences` 扩展为：

```ts
interface EncryptionPreferences {
  inputDir: string;
  outputDir: string;
  inputHistory: string[];
  outputHistory: string[];
}
```

- `inputHistory` 和 `outputHistory` 各自保存最近 10 条非空目录路径，最新使用的路径排在最前面，重复路径只保留一条。
- 读取旧版偏好文件时，缺失或非法的历史字段按空数组处理；如果旧版当前目录仍存在，则将它纳入对应历史，保证升级后已有选择可直接复用。
- 历史路径不因目录后来被删除而自动清除。读取偏好时仍按现有规则校验当前 `inputDir`、`outputDir` 是否存在；历史项被选中后，目录是否可用由现有加密任务校验负责。
- 保存目录时由偏好层根据 `inputDir` 或 `outputDir` 自动更新对应历史，调用方不直接提交历史数组。这样系统目录选择和手动输入使用同一套记录逻辑。

## 交互与数据流

每个加密目录输入框右侧增加一个历史箭头按钮：

1. 没有对应历史时按钮禁用；加密任务运行期间输入框、选择按钮和历史按钮全部禁用。
2. 点击箭头后，在当前输入框下方显示对应的历史目录列表，使用与转发地址一致的列表框、选项和点击外部关闭行为。
3. 点击历史项后，将路径填入当前字段，关闭菜单，并调用现有目录保存逻辑；保存成功后该路径置顶，保存失败时恢复上一次有效值并显示现有错误提示。
4. 通过系统目录选择器选择目录，或在输入框失焦/按 Enter 保存手动输入，均由同一个偏好保存接口记录历史。
5. 加密前和加密后历史使用不同的菜单状态与数据源，选择其中一项不会修改另一项。

数据流保持为：

```text
目录选择/手动输入
  -> ConfigPages
  -> preload encryption:save-preferences
  -> main preferences save
  -> preferences.json 的当前目录 + 对应历史
  -> getEncryptionPreferences 返回 Renderer
```

## 实现边界

- `src/core/encryption/preferences.ts` 负责历史数组的清洗、去重、最多 10 条限制以及旧数据迁移。
- `electron/main.ts` 和 `electron/preload.ts` 继续只暴露当前目录字段的受信任保存接口；历史由主进程偏好层生成，不新增 IPC channel。
- `src/shared/contracts.ts` 更新共享偏好类型和初始值使用点。
- `src/renderer/components/ConfigPages.tsx` 增加两个历史下拉入口、选择处理和外部点击关闭；复用转发地址历史的视觉类和可访问性语义。
- `src/renderer/styles.css` 只补充加密目录输入壳层/菜单所需布局，保持现有转发地址历史菜单视觉风格。

## 错误处理

- 取消系统目录选择不新增历史，也不显示错误。
- 空路径、非法 `file://` URL 或保存 IPC 失败沿用当前目录输入错误处理，不污染历史。
- 历史项可以指向已不存在的目录；选择时允许填入，开始加密时沿用现有“源目录不存在”或目录关系校验错误。
- 偏好文件中非字符串、空字符串和重复历史项会被忽略；单个字段损坏不影响另一个字段或当前目录读取。

## 测试计划

- 核心偏好测试：旧偏好兼容、当前目录迁移进历史、前后目录历史隔离、置顶去重、最多 10 条、历史路径保留。
- Renderer 合同测试：两个加密字段均有历史箭头、可访问性属性、历史菜单/选项、选择后复用保存函数、运行期间禁用，以及与转发地址样式复用。
- Electron/preload 合同测试：扩展后的偏好返回结构能够通过现有 IPC 和 preload 类型检查，保存接口仍拒绝未知字段。
- 运行 `npm test`、`npm run build` 和 `git diff --check` 做回归验证。
